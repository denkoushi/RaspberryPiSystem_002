# 切削の1台ずつ自動分割と工程ガント(PR2b)

PR1(#2682)の API と、段取りをロットで1回にする修正(#2709)の上に、製番ボードの画面側をつなぐ。API と shared-types は変えない。

## やったこと

- 自動分割: 製番ボードを開いている間、`POST .../pieces/auto-unit-split` を呼ぶ(`usePlanningBoardAutoUnitSplit.ts`)。1回の画面表示につき最大10回(失敗も数える)、応答のあと3秒以上空ける。`hasMore=false` で止める。失敗したら 6→12→24→最大30秒と待つ。オフラインの間は回数を使わない。画面を離れたらタイマーを消し、遅れた応答では読み直さない。同時に2本は走らせない。`splitCount>0` のときだけボードを読み直す。
- ガント: `unitRequiredMinutes` がある片だけ、その時間で棒を描く(`planningBoardUnitSegments.ts`)。`ops` を opNo 順に時間の比で区切り、`completedOpNos` の工程は済みの見た目にする。段取りは、同じレーンで直前と品番が変わる所にだけ、品番の値(own の資源のとき)の `setupMinutes` を斜線で足す。工程が変わっても足さない。納期から・今日から・1台の機械の表示のすべてに入れた。単位時間の無い棒は今までどおり。
- 工程の完了: 片のポップオーバーに工程ごとの完了/未完了のボタンを出し、`PUT .../ops/:opNo/completion` を呼ぶ。片の完了と同じ排他、楽観更新、失敗時の戻し、409/403 後の読み直しを使う。

## 決めたこと

- 接続の監視はこの画面につながっていないので、オフラインの判定は `navigator.onLine` を使う。
- ポップオーバーは、開いている間だけ中身を作る(閉じている片の分の状態やタイマーを作らない)。

## 確かめたこと

- web の型チェック(`tsc -b`)は合格。対象の単体テストも合格。
- 速さ: `__perf__/pageInteractions.perf.tsx` を pieces-only で、変更前のソース(392246bd)と変更後で1回ずつ測った(1,650項目、うち数量1の片50個×5工程)。結果は `__perf__/unit-before.json` と `unit-after.json`。配置の計算時間(ガントの保存完了 26.4→24.9ms)と行の描き直しの回数は前後で同じだった。片の完了は 375→373ms。ガントの保存完了は 106→129ms だが、測ったときの Mac の負荷は load average 30 で、各回のばらつき(101〜111 と 122〜167)の範囲に入る。工程と段取りの区切りで DOM が約2.5%増えた。
