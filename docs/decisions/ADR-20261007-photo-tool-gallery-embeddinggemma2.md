# ADR-20261007: 写真持出 類似ギャラリーの埋め込みモデルを EmbeddingGemma 2 へ

## Context

- 類似ギャラリー（[ADR-20260330](./ADR-20260330-photo-tool-similarity-gallery-pgvector.md)）は CLIP ViT-B/32（512 次元）の画像ベクトルを使っている。
- 2026-10 に公開された `google/embeddinggemma-2`（Apache 2.0、768 次元、先頭 512 / 256 / 128 次元へ切り詰め可）を、本番ギャラリーの写真で比較した。

測定（2026-10-07、Mac 上のオフライン、本番は変更なし）: GOOD ギャラリー 402 行・56 ラベル。CLIP は本番に保存済みのベクトル、EmbeddingGemma 2 は本番と同じ長辺 768 に縮小した写真から計算。各写真について自分以外の最近傍を見る（類似候補 API と同じ除外）。同じラベルの写真がほかにある 386 行が対象。

| 指標 | CLIP ViT-B/32 | EmbeddingGemma 2（512 次元） |
| --- | --- | --- |
| 最近傍が同じラベル | 346 / 386 | 372 / 386 |
| 上位 5 件の多数決が同じラベル | 330 / 386 | 355 / 386 |
| 上位 5 件に占める同じラベルの割合 | 0.816 | 0.943 |
| 行数 2〜4 のラベルで最近傍が同じラベル | 33 / 39 | 39 / 39 |
| 同ラベル対と異ラベル対の分離（AUC） | 0.870 | 0.970 |

- 写真ごとの対比較（最近傍の一致）は改善 31、悪化 3。768 次元は 374 / 386、256 次元は 376 / 386 で、512 次元との差は小さい。
- 同じ工具は似た構図で繰り返し撮られるため、どちらの数値も高めに出る。条件は同一なので差は比較できる。
- 距離の分布が変わる。最近傍距離の中央値は CLIP 0.063、EmbeddingGemma 2（512 次元）0.036。現在のしきい値のままでは緩すぎる。

| しきい値 | 候補のある写真 | 最近傍がしきい値内で同じラベル |
| --- | --- | --- |
| CLIP 0.14（補助の現行値） | 370 / 402 | 334 / 370 |
| CLIP 0.22（類似候補の現行値） | 399 / 402 | 346 / 399 |
| EmbeddingGemma 2 0.10 | 372 / 402 | 358 / 372 |
| EmbeddingGemma 2 0.14 | 387 / 402 | 370 / 387 |

- 日本語のラベル名から写真を引く使い方は弱い（ラベル 56 種で 1 位一致 33、写真から最も近いラベル名を選ぶと 159 / 402）。テキストからの写真検索は今回の対象にしない。

## Decision

1. 埋め込みサーバー（`scripts/dgx-local-llm-system/embedding-server.py`）に `EMBEDDING_BACKEND`（`clip` 既定 / `embeddinggemma2`）と `EMBEDDING_TRUNCATE_DIM` を追加する。既定動作と HTTP 契約は変えない。
2. 近傍検索とラベル別行数は、`embeddingModelId` が現在の設定と一致する行だけを対象にする。モデル切り替え後の再投入中に、別空間のベクトル同士を比べないためである。切り戻し時も旧モデルの行だけが使われる。
3. 切り替え後のモデル ID は `embeddinggemma-2-512d`、次元は 512（`vector(512)` の列は変更しない）。
4. しきい値は切り替えと同時に、類似候補 0.22 → 0.14、補助 0.14 → 0.10 とする。
5. 本番の切り替え（DGX のサーバー、Pi5 の設定、再投入）は、DGX 上での処理時間を別ポートで測ってから行う。

## Alternatives

- **768 次元で保存**: 列の型変更と HNSW 索引の作り直しが必要で、512 次元との差は 2 行。見送り。
- **CLIP の大きいモデルへ変更**: 未測定。EmbeddingGemma 2 で十分な差が出たため比較していない。
- **モデル ID で絞らず一括で入れ替える**: 再投入の間（402 行）、新旧のベクトルが混ざって距離が無意味になる。却下。

## Consequences

- **良い**: 類似候補と補助の入力が正確になる。行数の少ないラベルで効果が大きい。
- **悪い / 注意**: モデルは CLIP より大きい（テキストと画像で約 440M パラメータ）。Mac の CPU では 1 枚 25 秒前後かかり、API の既定タイムアウト（30 秒）に近い。DGX では GPU で動かすか、CPU の所要時間を測って判断する。sentence-transformers 6.1.0 以上が必要で、現行コンテナ（`lmsysorg/sglang:latest`）で動くかは未確認。
- 切り替え直後は、再投入が終わるまで類似候補が少ない（モデル ID で絞るため）。
- しきい値は 402 行での値であり、切り替え後にシャドーのログで再確認する。
