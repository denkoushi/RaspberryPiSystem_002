# ADR-20261125: 工程の資源を付け替えたとき、付け替え先の完了(C)を元の行の完了として保存する

- **Status**: accepted
- **Amends**: [ADR-20260509](./ADR-20260509-fkojunst-status-completion-matching-policy.md) の決定1(3つの厳密一致)と決定5(対応行の無い C は無視)
- **Context**:
  - 現場は工程の負荷を避けるため、生産システムで工程の資源(機械)をよく付け替える(2026-11-25 ユーザー回答)。
  - 付け替えると、`FKOJUNST_Status` には付け替え先の資源の行ができ、P→R→C と進む。生産日程 CSV は元の資源のまま。
  - ADR-20260509 の決定1では資源まで一致しないと完了にしないので、元の行が未完了のまま残る。製番ボード、負荷集計、納期管理、進捗一覧、モバイルで未完了として数えられる。
  - 2026-11-25 の本番データでは、部品の行 129 行で別資源に C/X が付いていた。調べると、どの行でも状態側の別資源はちょうど1つだった([KB-456](../knowledge-base/KB-456-fkojunst-completion-on-swapped-resource.md))。
  - 次の工程の「着」の判定は、#2889 で付け替えの C を完了とみなしている。前の工程の行だけが未完了で残る食い違いが出ていた。
- **Decision**:
  1. 生産日程の winner 行(ProductNo n、FKOJUN j、資源 r)は、次を全部満たすとき「付け替え完了」として外部完了に保存する。保存先は `ProductionScheduleExternalCompletion.externallyCompletedFromFkojunstResourceSwap`。`isExternallyCompleted` はメール由来の C/X との OR とする。
     - 同じ n・j で、r 以外の資源の状態がちょうど1つ。その最新状態(FUPDTEDT 最新)が `C` である。
     - その n・j に、生産日程の winner 行が1行だけ。除外資源の winner 行は数えない(本番では同じ工順に資源 `10` の行が並ぶことが多い)。
       - 例外(2026-11-26 追加): r 自身の最新状態が `R` なら、winner 行が2行以上でも適用する。このとき別資源の状態には、もう一方の winner 行に一致した状態も含める。別資源がちょうど1つ、相手が `C`、r の `R` が相手の `C` と同じか古いことは変えない。負荷集計用の資源は今までどおり winner 1行のときだけ。
     - r 自身に状態があるなら、それは `S` ではない。かつ、別資源の C の方が同じか新しい。
     - r も別資源も除外資源(`cuttingExcludedResourceCds`。組立 `KUMITATE1/2` などを含む)ではない。
  2. `X` は付け替え完了に含めない(#2889 の「着」にそろえる)。
  3. 製造オーダと工順は厳密一致のまま。緩めるのは資源だけで、相手が1つに決まるときに限る。
  4. 再計算の時点、最新を勝者にすること、取り消しを許すことは、ADR-20260509 の決定3・4をそのまま適用する。別資源の最新が C でなくなれば、付け替え完了も外れる。
  5. 判定の材料には、メール同期で 3つ一致しなかった状態行を証拠テーブルに保存したものを使う。外部完了の再計算はこのテーブルを読む。表示のたびに状態 CSV の原本を読まない。保存するのは、生産日程に winner のある工程(n・j)の状態だけにする(状態 CSV の全履歴は約 92 万の組、残るのは約 2.8 万行)。
  6. 同じ前提で付け替え先が S/R/O/P かつ資源マスタにある場合は、外部完了の再計算で負荷集計用の資源を保存し、負荷の数字だけを付け替え先に計上する。マスタにない場合は元の機械に計上する(負荷調整は元から、自分の資源に状態の無い行を数えないので、その行は数えないまま)。行の表示と順位には元の資源を使う。
- **Out of scope**:
  - 組立の行の番号体系のずれ(`KUMITATE1/2` と `301`/`306`/`309`/`311`/`434`)。[KB-373](../knowledge-base/KB-373-fkojunst-status-c-key-domain-mismatch.md) と同じ種類で、この規則では除外資源として外す。
- **Alternatives**:
  - **A**: 製番ボードの表示だけで完了とみなす(#2889 と同じ形)。採らない。負荷集計・納期管理・進捗・モバイルでは未完了のまま残り、付け替えはよくあるので食い違いが続く。
  - **B**: 画面ごとに読むときに判定する。採らない。完了を読む所が約40ファイルあり、漏れが出る。読むたびに状態 CSV を当たるので遅い。
  - **C**: 別資源の X も含める。採らない。「着」の判定とずれる。X の意味(場外)が完了と同じとは限らない。
- **Consequences**:
  - **良**: 付け替えた工程が、すべての画面で同じように完了になる。「着」との食い違いが消える。
  - **悪**: 状態側の資源が1つに決まらない行(別資源が2つ、または winner が2行で自分が `R` 以外)は、今までどおり未完了で残る。現場が手で完了にする運用が少し残る。
  - winner 2行の例外を `R` だけにした理由(2026-11-26 ユーザー判断): `R` で止まった資源は、付け替えで使われなくなった工程とみなせる。`O` は外した。`O` の大半は10桁の工程コード(工場の加工工程の外)で、機械の資源で相手が `C` なのは16行だけだった。`P`・`S`・状態なしも対象外。
  - **悪**: 完了をきっかけに動く処理が、付け替え完了でも動く。完了で消した順位の割り当てと、製番ボードから外れた登録製番は、完了が外れても戻らない(メール由来の C/X と同じ)。反映時点で、対象の行に割り当ては 0 行。
  - **悪**: 状態 CSV が空で届いたときは、付け替え完了だけを外す(メール由来の完了は残す)。次の同期で戻る。
  - 生産日程の取り込み後の再計算でも証拠を置き換えるので、その transaction の上限をメール同期と同じ 300 秒にした。
  - **悪**: 自分の資源が `R` のまま付け替え先が `C` の行も完了になる(2026-11-25 で 149 行)。同じ製造オーダ・工順を別の機械で終えたので、作業は済んだとみなす。
- **Validation**:
  - 規則の単体テスト(C は完了、X は対象外、winner 2行は対象外、別資源2つは対象外、自分が S は対象外、組立は対象外、別資源が C でなくなると外れる)。
  - 本番への反映の前に、同じ規則の読み取りだけの SELECT で件数を出した(2026-11-25)。新しく完了になるのは 821 行、製番ボードの登録製番で 57 行。最新の取り込みだけで数えた KB-456 の見込み(112 行)は、このうち「最新の取り込みで、自分の資源に状態が無い」106 行にあたる。内訳と SQL は KB-456。
  - `R` の例外を足す前に、実装と同じ SQL を本番で読むだけで流した(2026-11-26)。新しく完了になるのは 213 行、製番ボードの登録製番で 15 行。今まで完了だった行で外れるものは 0 行。例: 製造オーダ `0004174191`・`0004174221` の工順200 で、資源 `26M`(R、10/20)が `24M` の C(11/16・11/17)で完了になる。
