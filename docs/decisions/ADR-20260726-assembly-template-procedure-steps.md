# ADR-20260726: 組立テンプレート版が表示ステップを所有する

## Context

現在の組立テンプレート版は文書順を所有するが、表示単位は各文書の全ページに固定されている。同じページの一部を独立した手順として再掲し、順序、指示、重要度を付ける要求を満たせない。丸数字、チェック、矢視は既に元文書・ページ・比率座標を正本としている。

## Decision

`AssemblyTemplateProcedureItem` は利用文書集合として維持し、テンプレート版が別の `AssemblyTemplateProcedureStep` を所有する。ステップは元文書、元ページ、全体または矩形、タイトル、平文指示、重要度、全体順序を保持する。crop画像ファイルは生成せず、元ページと比率矩形から表示する。

丸数字、チェック、矢視は元ページ座標を正本のまま共有する。cropではアンカーが矩形内にあるマーカーだけをステップ座標へ変換する。明示ステップを保存する場合、既存マーカーが少なくとも1ステップで表示可能でなければ拒否する。

既存テンプレートはバックフィルしない。保存済みステップがなければ、現在の文書順とページ順から全体ステップを動的に合成する。APIの既存文書レスポンスは残し、ステップレスポンスを追加する。

閲覧履歴と閲覧完了ゲートは追加しない。作業完了条件は締付と必須チェックのままとする。

## Consequences

- 同じ元ページを全体と複数cropで再利用でき、画像容量は増えない。
- テンプレート版と開始済み作業セッションの再現性を維持できる。
- 旧テンプレートと旧クライアントはDB更新なしで動作する。
- 文書順と表示順は別概念になるため、APIサービスが両者の整合を検証する。
- crop表示ではマーカーと矢視の座標変換が必要になる。
- 300件規模では全件DOM表示を避け、仮想化と画像キャッシュが必須になる。

## Rejected Alternatives

- crop画像を保存する案は、元PDFを保持しておらず画質を増やせないうえ、容量・削除・バックアップ責務を増やすため採用しない。
- 既存の文書項目を表示ステップへ兼用する案は、文書集合と表示順の責務を混在させ、同一ページ再利用と互換展開を複雑にするため採用しない。
- マーカーを各ステップへ複製する案は、同じ締付点の条件と座標が分岐するため採用しない。
