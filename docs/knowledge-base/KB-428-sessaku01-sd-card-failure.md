# KB-428: 切削01（raspi4-sessaku-01）の SD カード破損と、回収したカードの検査

- Status: active
- Date: 2026-10-29
- Scope: `raspi4-sessaku-01` の旧 SD カード。同じ型と製造時期のカードを使う `raspi4-robodrill01` と `raspi4-kensaku-stonebase01` の交換判断。Pi5 と他の Pi4 の設定は変えていない

## 起きたこと（2026-10-22）

- 12:53 頃、切削01 のルートファイルシステムで `Corrupt inode bitmap`（検査値 CRC の不一致）が出て、端末が正常に動かなくなった。
- カードは `SD32G`、製造 2022-07、manfid `0x27`。ファイルシステムの累計書き込みは 141GB。
- 同じ型・同じ時期のカードを `raspi4-robodrill01`（約 385GB 書き込み済み）と `raspi4-kensaku-stonebase01`（約 408GB）が使っている。
- 切削01 は新しいカードへ書き戻して復旧した（Pi5 の SD スロットへの書き戻しは PR #2320）。
- ストレージ異常の通知がチャットで目立たなかったため、1 時間ごとに繰り返すようにした（PR #2330）。
- 旧カードは一時行方不明になり、10/29 に見つかった。

## 回収したカードの検査（2026-10-29）

### 方法

- Mac に USB カードリーダー（Genesys Logic `05e3:0749`）をつなぎ、読み取りだけで検査した。カードへは書き込んでいない。
- macOS は起動用の FAT 領域を読み取り専用で自動的に開いたが、すぐに閉じた。
- 全体を読む検査: `/dev/rdisk4` を 1MiB ずつ読み、読めない場所（64KiB 単位で再読）と、1MiB の読み取りに 0.25 秒を超える遅い場所を記録した。各 1MiB の SHA-1 も残した。
- ファイルシステムの検査: Homebrew の `e2fsprogs` で `dumpe2fs -h` と `e2fsck -fn`（読み取り専用、修復なし）を実行した。

### 結果

- 全 31,268,536,320 バイト（31.3GB）を 413 秒で読めた。読めない場所は 0、遅い場所は 0 だった。
- 容量は 32GB 表示のカードとして普通の値だった。データはカード全体（0〜29GB）に散らばっていて、同じ内容が周期的に繰り返す偽容量カードの兆候はなかった。
- macOS が `Media Read-Only: Yes` を報告した。microSD なのでロックつまみはない。カード自身が書き込みを止めている（故障したカードが自分で書き込みを止める典型の状態）と判断した。カードリーダー側が読み取り専用を報告している可能性は残る。
- ファイルシステムは 10/22 の電源断のままで、`needs_recovery`（ジャーナル未反映）が立っていた。最後のマウントは 10/22 13:17、最後の書き込みは 10/23 02:20。
- `e2fsck -fn` は、ジャーナルを反映しない状態で次を報告した。大きな壊れ方はなかった。
  - ブロック一覧の検査値の不一致 2 か所（group 86 と 116）
  - 削除済み inode の dtime なし 5 件と、それに伴うブロック・inode 一覧と空き数のずれ
  - orphan file の未整理
- 10/22 に出た inode 一覧の CRC 不一致そのものは、今回の読み取りでは再現しなかった。ジャーナルを反映していないので、確定ではない。

## 結論

- 傷みが広がって読めなくなる寿命切れではない。全体が読め、遅い場所もない。累計書き込みは同じ型の 2 台より少ない。
- カードが自分で書き込みを止めていることから、このカード 1 枚の不良（制御部の故障）の可能性が高い。
- `raspi4-robodrill01` と `raspi4-kensaku-stonebase01` は今すぐの交換は不要。2026-10-27 の SD 全体の控えがあるので、USB SSD の試験に合わせて計画的に交換する。
- カードは回収済みなので、切削01 のホスト名と鍵の作り直しは不要とした。

## 旧カードの扱い

- 切削01 のホスト名と鍵が入っているので、他の Pi に挿して起動しない。使用禁止として保管する。
- カードが書き込みを止めていて中身を消せないため、処分するときは物理的に壊す。
