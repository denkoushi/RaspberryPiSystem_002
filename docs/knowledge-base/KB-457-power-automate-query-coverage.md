# KB-457: Power Automate の取り込みクエリが届けるデータの範囲(購買の品番絞り込みと、工順STに出ない資源)

- 状態: ✅ 調査完了(購買はクエリ修正と過去分の取り込み済み、工順STはクエリ修正不要)
- 対象: Power Automate → Power BI データセットへの DAX クエリ → Gmail CSV → Pi5 の取り込み
- 日付: 2026-11-26

## 背景

モバイルの「照合の記録」で、後から購買データが入れば照合OKになるはずの行が「?」のまま残っていた。
購買 CSV に注文番号が無いことが原因だったため、同じ作りの工順ST(FKOJUNST_Status)の取り込みにも、同じような抜けがないかを調べた。

## 1. 購買 CSV(PurchaseOrder_FKOBAINO)

- Power Automate のフロー「SCAWから注文コードを取得」が、データセット `scawSTKOBAI` に DAX を投げて CSV を作る。
- 原因: クエリが品番を MD/HMD に絞っていた。SD・ZD など MD 以外の購買は一度も届いておらず、照合が「?」になっていた。
- 修正(ユーザーが Power Automate 側で実施): 品番の条件を外し、期間を `>= TODAY() - 6` だけにした。`TODAY()` は UTC なので、朝 6:30 の実行では前日扱いになる。上限の `< TODAY()` を付けると、前日分が翌々日まで届かない。
- 過去分: 2025/1/1〜2026/11/20 の MD 以外を6回に分けて手動で取り込んだ。どの回も 10万行未満で欠けはなく、購買データは 580,111 行になった。
- 期間の長いクエリで表全体を `FILTER` すると、メモリ上限(1331MB)で止まる。`FILTER(ALL(列), …)` のように列ごとに絞る。
- 取り込み直し後の照合: 抜けていた5件のうち4件が match になった。残る `0004076174` × `0005994910` は different_seiban(現品票 BA1SA361、移動票 BA1SB354)。現場での取り違えの確認をユーザーに依頼した。

## 2. 工順ST CSV(FKOJUNST_Status)

フロー `Gmail_CSV_工順STアップロード_Direct` が、データセット `scawFKOJUNST` の表 `scaw STKOJUNSEZO` から次の条件で取る。

- `FKOJUNST IN { "S", "R", "C", "P", "O", "X" }`
- `FUPDTEDT` が空でなく、`TODAY() - 6` 以上 `TODAY() + 1` 未満

品番や資源の絞り込みは無い。

### 本番 DB で見たこと(2026-11-26)

- 取り込みはほぼ毎日動いている。10/21・10/29・11/21 は届いていないが、毎回7日分を取り直すので、その日の分も翌日以降に入っている。
- 機械の資源(587、584、021 など)は、生産日程の行の 8〜9 割に工順STが付いている。11 月の新しい注文で付いていないのは、まだ手を付けていない工程。
- 次の資源は、これまでに受け取った約 97 万行に一度も出ていない(050 は 4 行だけ)。

| 資源 | 名前 | 生産日程の行数 |
|---|---|---|
| `10` | 研磨人員 | 約 42,000 |
| `MSZ` | 三島製造課 | 約 21,000 |
| `KUMITATE1` / `KUMITATE2` | 組立 | 約 6,900 |
| `SKKT`、`SFAK` | — | 合わせて約 320 |

- このため、品番の頭が MH・SH・SA・SI の組立品には、工順STが1件も付いていない。

### Power BI 側での確認

クエリを一時的に次の内容に置き換えて、フローの「テスト」で実行した(条件なしで全件を集計する)。

```
EVALUATE
SUMMARIZECOLUMNS(
    'scaw STKOJUNSEZO'[FKOTEICD],
    'scaw STKOJUNSEZO'[FKOJUNST],
    "件数", COUNTROWS('scaw STKOJUNSEZO')
)
```

- 状態は S・R・C・P・O・X の6種類だけで、空欄やほかの値は無い。状態の条件で落ちている行は無い。
- 上の表の資源は、条件なしでも1件も無い。データセットそのものに入っていない。
- 外注先の番号(1143016000 など)や機械の資源は入っている。

### 結論

- 工順STのクエリは直す必要がない。
- 研磨人員・三島製造課・組立などの完了は、自動では付かず、画面から手で付ける(今の動きどおり)。
- それらの工程の状態を生産管理システムで入れていないのか、データセットの元の表に入らない作りなのかは、まだ分からない。自動化したくなったら、生産管理システムの担当に確認するところから始める。

## 同じ症状を調べるとき

1. 照合や完了が付かない行の品番・資源を、Pi5 の DB で頭文字ごと・資源ごとに集計し、「1件も付かない群」が無いかを見る。
2. あれば、そのフローのクエリ(Power Automate の「データセットに対してクエリを実行する」)の条件を読む。
3. クエリに条件が無ければ、上のような条件なしの集計クエリを「テスト」で流し、データセットにその群があるかを確かめる。テスト後はクエリを元に戻す。
