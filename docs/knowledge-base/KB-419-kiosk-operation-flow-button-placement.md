# KB-419: キオスクのボタン配置を操作の順番に合わせて直した（要領書の「作る」ほか）

- Status: `active`
- Scope: `apps/web` キオスク画面（組立・要領書・持出一覧・自主検査・部品測定の記録編集・フローティングChat）

## Context

2026-10-13。組立＞要領書＞「作る・直す」で「＋作る」が右上にあり、左ペインで機種と工程を選んでから押すという順番に合っていなかった。同じ種類の問題が他画面にもないか調べ、見つかったものをまとめて直した。

## Symptoms Or Trigger

- 条件を選ぶ場所と、選んだ後に押すボタンが画面の反対側にある。
- 取り返しのつかない操作（やり直し、取消、削除、初期化）が、いちばんよく押すボタンのすぐ隣にあり、確認もない。
- 確認ダイアログの「やめる側」と「実行する側」の左右が画面ごとに違う。
- 一覧の先頭に戻るボタンとその画面の主ボタンが、同じ見た目で並んでいる。

## Root Cause

画面ごとに空いた場所へボタンを足してきたため。配置の決まりが文書になっていなかった。

## Fix

配置の決まり（今後の画面もこれに合わせる）:

1. 条件を選んでから押すボタンは、条件を選ぶ場所のすぐ近くに置き、条件が揃ったときだけ表示する。表示の有無で下の部品が動かないよう、場所の高さは常に確保する。
2. 取り返しのつかない操作は主ボタンから離し、確認ダイアログを挟む。
3. 確認は「やめる」を左、「実行」を右にする（`components/ui/ConfirmDialog.tsx` と同じ）。
4. 画面を出るボタンは編集ツールの並びの先頭に置き、削除は末尾に単独で置く。

画面別の変更:

| 画面 | 変更 |
| --- | --- |
| 要領書「作る・直す」 | 「作る」「＋ 既存を割り当てる」を左ペインの上辺へ。機種/部品と工程（共通は分類）を選んだときだけ表示 |
| 要領書「見る」 | 画面上部の帯を全モードで1本に統一 |
| 組立の作業画面 | 「やり直し」を履歴の下へ移し、確認を追加。戻るボタンの表記を「組立へ戻る」に統一 |
| 製品構成・正式ID | 変更先と理由の入力を確認ダイアログの中へ。未入力の間は確定できない |
| 組立トップ | ロット登録の欄を左側へ |
| 組立の手順書一覧 | 登録ボタンをタブの直後へ。テンプレートのタブに「＋ 手順書から作る」を追加 |
| 手順書・テンプレートの編集画面 | 戻るボタンを縦ツールバーの先頭へ、削除を末尾に単独で配置 |
| 手順書プレビュー | 「閉じる」を左、「確認して公開」を右 |
| 持出一覧のカード | 「取消」を右上へ移し確認を追加、「返却」は下段いっぱい。カードの高さを 260px → 304px（取消の段を足しても本文の高さを以前とほぼ同じに保つため） |
| 自主検査 | 「次の測定点」を「入力を保存」の右へ、「自主検査を完了」は別の段へ、「初期化」はヘッダー左端へ。一覧の「削除」を左端へ離す |
| 部品測定の記録編集 | 確認の並びを やめる左／実行右 に統一。「下書き取消」を左端へ離す |
| フローティングChat | 利用者が動かしたアイコンの位置を端末ごとに記憶（`localStorage` の `hermes-chat-icon-position`）。画面右下のボタンと重なるときに動かしたままにできる |

持出カードの配置は [KB-323](./KB-323-kiosk-return-card-button-layout.md) の「返却・取消を下段に並べる」を置き換える。

## Prevention

- 上の決まり1〜4を新しいキオスク画面の確認項目にする。
- 各画面のテストで、ボタンの並び順と確認ダイアログを通ることを確かめている。

## Validation

- `apps/web`: `pnpm exec tsc --noEmit -p .`、`pnpm exec eslint src --ext .ts,.tsx`、`pnpm exec vitest run`（525ファイル）。
- 取説画像: `pnpm kiosk-sop:source-check`。

## Open Items

- 調査していない画面: 生産スケジュール、配膳スマホ、パレット可視化、検査図面の編集・印刷。
- 「閉じる／やめる／キャンセル」の表記統一は、今回触ったダイアログだけ。
- 自主検査一覧の行内ボタンは従来どおり高さ約31pxのまま。
