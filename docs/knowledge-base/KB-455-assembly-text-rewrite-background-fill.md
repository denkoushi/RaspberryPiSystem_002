# KB-455: 要領書エディタ「文字を書き換える」の消し跡が背景になじまない

- Status: ローカル実装済み・実機確認待ち
- Scope: API `apps/api/src/services/image-region/text-erase.ts`(`eraseText`)
- Date: 2026-11-19

## Symptoms

要領書エディタで「文字を書き換える」と、元の文字を消した所がぼけた帯になり、紙の粒・写真の筋・罫線・色の傾きが周りとつながらない。

## Cause

旧実装は OCR の枠全体(余白付き)をマスクし、半径22の箱平均を収束しない反復でならして白色雑音を足していた。文字の線ではなく枠全体を塗るため、模様が消えて帯になる。

## Fix

1. 文字の線だけのマスクを作る(Otsu の芯 → 3px までの弱い画素へ伸長 → 半径2の膨張)。芯の密度が 0.45 を超える枠は枠全体を消す。
2. 長い直線(罫線)は消さずに残し、文字の下を通る薄い罫線は両端から補間する。
3. マスクの連結成分ごとに、周りの輪と最もなじむずらし量を粗い探索(6px刻み)から細かい探索で選び、その位置の画素を写す。
4. 境界の色の差を SOR で滑らかに補正する(通常40回、枠全体の場合400回)。写す元が無い成分は周りの色からの滑らかな塗りにする。

外部の AI サービスは使わない。保存形式、Web 側、DB は変えていない。

## Validation

- 合成見本7種(紙の粒、罫線、写真の筋、色地の点模様、斜めの筋、詰まった段落、少し傾いた罫線)で、文字の画素の平均誤差が旧 6.4〜11.4 から 2.4〜9.7 に下がった。比較ページ: https://claude.ai/artifact/TJFkATmpR7m5RfGQFTDZE8
- 2000×2000 に10行の最悪例で、Mac で旧 3.4 秒 → 新 2.2 秒。
- `text-erase.quality.test.ts` の罫線と粒のテストは旧実装では落ちる。

## Open Items
