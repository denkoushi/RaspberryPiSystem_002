# KB-420: 手順書の「整える」に組立の現場の知識を持たせた

- Status: `active`
- Scope: `apps/api` 組立＞手順書＞作る・直す の「整える」（文章の書き直し）

## Context

2026-10-14。「整える」が提案する文章を賢くしたい。課題は、業務LLMが現場のことを何も知らないまま文章を書き直していたこと（指示文にあったのは一般的な書き方の規則と見本1つだけ）。

## Fix

- 素材ウインドウに入っていた既存の組立作業標準書（DFL7161XY高精度2、表紙＋20工程の21枚）を、今回かぎりの作業としてフロンティアモデル（Claude）が全ページ読み、現場の理解をまとめた。社外への送信は利用者の承認済み。
- まとめのうち業務LLMに毎回渡す要約を `apps/api/src/services/assembly/procedure-site-context.ts` に置き、「整える」の文章用の指示文へ差し込んだ。
- 知識は入力の意味を理解するためだけに使わせる。入力に無い部品・数値・作業を足さない規則は残し、聞き違い・誤変換と分かる語だけ現場の語に直す規則を足した。
- 写真の説明文（1行の提案）の指示は変えていない。

## 現場の理解（出典の全体）

【原本】= 原本に書いてあること。【推定】= 原本と一般的な機械の知識から補ったこと。

### 1. 何を作っている現場か

- 組立課が、精密な位置決めステージ(X軸・Y軸の2段重ね)を1台ずつ手で組み立てている。【原本】
- 「高精度」品。μm 単位の測定と調整が工程に組み込まれている(ダイヤルゲージは 2μm と 10μm を使い分け)。【原本】
- 大きく重い部品を扱う。サドルはクレーンで吊る。ベースにはアイボルトが付いている。【原本】

### 2. 製品の成り立ち(下から上へ)

1. ベース(本体ベース): 土台。黒い塗装の鋳物で、部品が載る面だけ研削されている。足(L,R)が付く。
2. 下の軸: ベースの上に LMガイド(レール2本+ガイドブロック)と ボールねじASSY を付ける。
3. サドル: 下の軸の上を動く中間の台。裏面にセンサー用のドグとタイマウントを付けてから載せる。
4. 上の軸: サドルの上にまた LMガイドを付け、リニアスケールとリニアモーターを組む。
5. テーブル: 一番上の、物を載せる台。
- 下の軸はボールねじで動かし、上の軸はリニアモーターで動かす。【推定: 原本ではボールねじの工程がサドル取付の前、リニアモーターの工程がテーブル取付の後にある】

### 3. 部品とその役目

- LMガイド(LMレール、ガイドブロック): まっすぐ滑らせる案内。レールを研削面に当てて締める。
- Cキャップ: レールのボルト穴をふさぐ栓。プラハンと専用治具で打ち込む。【推定: 役目】
- ボールねじASSY: 回転を直線の動きに変える送りねじ。モータブラケット(モーター側)と支持ブラケット(反対側)で両端を支える。
- ナット、ナットホルダー: ボールねじのナットを台(サドルやテーブル)につなぐ部品。
- ストッパー、ストッパー台、非常停止用ストッパー(アブソーバー): 動く範囲の端で止める部品。モーター側と反モーター側にある。
- ドグ(センサードグ): センサーに位置を知らせる板。
- マニホールド、グリスニップル、エルボユニオン、ハーフユニオン、ナイロンチューブ(配管): グリスを各所へ送る経路。
- スケール、スケールホルダー、スケール押さえ、中間板、スケールヘッド、スケールヘッド台: 位置を読むリニアスケール一式。スケールには向きがある(原点マークが上)。
- リニアモーター、固定子(=マグネット): 上の軸の駆動。マグネットはサイズが2種類あり、位置は図面で確認する。
- 足(L,R): 左右の刻印を合わせて付ける。

### 4. 作業の種類と、何のためにするか

- マスキング剥がし → 砥石掛け: 塗装時の養生を外し、取付面のバリや打痕を手持ちの砥石でならす。面をきれいにしてから精密部品を載せる。
- 取付(仮に付ける)→ 締付(規定トルクで締める): 2段階。締付はトルクレンチで行う。
- シャコマン: レールを基準面に押し当てたまま締めるためのクランプ。
- 突き当て: 部品を基準になる相手に当てて位置を決めること(例: サドルを反M側ストッパーに突き当てる)。
- 芯振れ・高さ・平行出し: ボールねじをてこ式ダイヤルゲージで測り、ずれを調整する。調整が済んでからブラケットを本締めする。
- 部組: 本体に付ける前に、小さな部品同士を先に組んでおくこと。
- 補修塗装(タッチアップ): 作業で出た金属の地肌を筆で黒く塗る。防錆油が付いた所は脱脂してから。
- グリスアップ: グリスガンで決まった箇所に決まった回数だけ給脂する。
- 起動トルク測定、ストローク確認: 動きの重さと動く距離の検査。
- 防錆(防錆処置): 塗装していない加工面に防錆油やグリスを塗る。

### 5. この現場で大事にされていること

- 締付トルクはボルトのサイズごとに決まっていて、必ず数値で指示する。管理しない締付は「手締め」と明記する。
- 締めた証拠を残す: 締付時に青マーカ、別の作業者が確認してピンクマーカ。ピンクを後の精度検査工程で入れる箇所もある。
- 規格値(合否の数値)は作業標準書には書かず、「要素」と呼ぶ個別の作業要領書(産1-U…BBC など)に任せる。作業標準書は流れ、要素は1作業の詳しいやり方。
- 取り違え防止の注意が多い: 向き(スケール、スケールヘッド)、左右(足の刻印)、種類(マグネット2種)、位置(写真の赤丸・A/B/C)。
- 改訂した箇所は赤字と △1 で示す。
- 保護具(手袋、保護メガネ)を工程ごとに書く。

### 6. 同じものを指す言い方

- 固定子 = マグネット
- ドグ = センサードグ
- 補修塗装 = タッチアップ
- 反モーター側 = 反M側
- LMガイド ≒ ガイド(レールだけを指すときは LMレール)
- グリスアップ = グリースアップ
- プラハン = プラスチックハンマー、シャコマン = C形クランプ【推定】

### 7. 現場に確認して分かった言葉

- KB = 基準側。反KB = 基準側の反対面。(LMレールを付ける面の呼び名。写真のラベルは「K」「反」)
- AFF = グリースの型番。
- DSW6、DSWC6、DSWC10 などはボルトの型番として扱う。

## 2026-10-20 追記: 組立の手順書だけに使う

- 本番の試し実行で、研削の文書にも組立の知識が渡り、「イケール」が「スケール」に、「0.2までなら加工してよい」が「0.2以内なら加工開始」に書き換わった。組立の文書では「車高マン→シャコマン」「反えむ→反M」「ケービー→KB」「エーエフエフ→AFF」が正しく直っていた。
- 直し方: 手順書の版の系列（revisionRootId）のどれかが、名前が「組立」で始まる工程（または親工程）に割り当てられているときだけ、知識と言い直しの決まりを渡す。割り当てが無い文書・研削など他の工程の文書は、知識を入れる前と同じ指示文になる。
- 決まりに「知識にある語に似ているだけでは置き換えない。知識に無い語はそのまま残す。」を足した。同じ試し文で、組立の知識を渡しても「イケール」が残り、組立の4件の言い直しは変わらないことを確かめた。
- 注意: 組立の手順書でも、手順書の割り当て（組立工程の下）が無いうちは知識が使われない。

## 2026-10-20 追記: 研削の現場の知識

- 本番の研削の手順書16冊(工程「研削」に割り当て済み)の文章を読み、`GRINDING_SITE_CONTEXT` を作った。工程番号とNCプログラム番号、マグネットチャックと治具(コマ、ジャッキ、ブロック、イケール、シム)、通りだしなどの合わせ方、M0・切り込み・砥石幅などの加工の言葉。
- 手順書の割り当ての工程名(または親工程名)が「組立」で始まれば組立の知識を、「研削」で始まれば研削の知識を渡す。どちらでもなければ知識なし。組立と研削の両方に割り当てられていれば組立を優先する。
- 本番の業務LLMで研削の文26件を試した(保存なし)。「胃ケール→イケール」「磁力マックス→磁力MAX」「3ミクロン→3μ」に直り、「イケール」「0.2までの傾き」は残った。最初の版では正しい「磁力最大」が「磁力MAX」に書き換わったため、「どちらの書き方もそのまま残す」と知識に書いた。
- 切削など、ほかの課の手順書が増えたら、同じやり方で文書を読んでから知識を足す。

## 2026-10-20 追記: 写真が1ページに収まらない場合

- 通常の配置が `Page does not fit` になる場合だけ、写真の一律縮小（98%から50%まで2%刻み、収まる最大値）と2ページ分割を計算する。文字には既存の縮小規則を使い、写真に付いた図形と端点も追従する。
- 分割は写真行の順番を維持し、両ページが収まる位置のうち最大列高が最小の位置を選ぶ。同点なら現在ページに多く残す。成立する候補だけ200応答の `overflow` に返し、どちらも無理なら従来の422を返す。
- 分割適用は `pages/blank` の `afterPageIndex` で直後に同寸法の白紙を挿入する。トランザクション内で後続ページと動画リンクを降順更新し、overlayは既存FKの `ON UPDATE CASCADE` に任せる。caption feedbackは後続ページ分だけ補正し、提案時には元ページ番号を記録する。
- 後続ページを参照するテンプレートの工程・ボルト・チェック項目があれば409で拒否する。アクセス認証・編集lease・DRAFT head・editVersionの既存ガードも維持する。
- Webは現在の未保存要素・Undo/Redo履歴・dirty判定基準を同じ番号へ補正し、分割配置を未保存編集として適用する。Undoで挿入済み白紙は残る。キャンバスには前半を表示し「残りは次の新しいページへ」と案内する。
- 回帰確認: APIの `procedure-layout.test.ts`、`procedure-insert-page.test.ts`、layout/revision routeテスト、Webのlayout hook・controller・画面テスト。ページ挿入のDB操作はPrisma mockで確認し、実DBのカスケード検証は含まない。

## Prevention / 注意

- 組立の知識の出典は組立の文書1冊、研削の知識の出典は研削の手順書16冊。「砥石」は組立では手持ちの砥石、研削では回る砥石で意味が違う。別の課の文書を読んだら、この KB と `procedure-site-context.ts` に足す。
- 型式（LMガイドや継手の型番）、文書番号、人名、社名は指示文に入れない。
- 現場の理解を直すときは、この KB を先に直し、要約を合わせる。

「整える」の提案と保存後の人の修正を記録し、同じ課の次回提案と夜間の用語学習に使う仕組みを追加した。
仕様と検証記録は[学習ループの実装計画](../plans/procedure-tidy-learning-loop-execplan.md)を参照する。本番反映は未実施。

写真の説明文も、同じ課の人の直し（EDITED、最新50件から1行30字以内・重複なしの最大5例）を次回提案に渡す。課不明では取得せず、夜間の語彙学習には混ぜない。
本番の研削の直し15件では「重り→コマ」「電磁チャック→マグネットチャック」などがほぼ共通したため、研削の写真指示文をコマ・ジャッキ・ブロックなど現場の呼び名に合わせた。
採用状況の確認は読み取り専用SQLで、課・結果別の件数を比較する（PROPOSEDは未確定）。
```sql
SELECT 'text' AS kind, site, outcome::text, count(*) FROM "AssemblyProcedureTextFeedback"
GROUP BY site, outcome
UNION ALL
SELECT 'caption' AS kind, site, outcome::text, count(*) FROM "AssemblyProcedureCaptionFeedback"
GROUP BY site, outcome ORDER BY kind, site, outcome;
```
